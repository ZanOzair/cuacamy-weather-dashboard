          Turn on Google sign-in

          Google will not let any website use its accounts until that site is registered with Google. That is a rule on Google's side, not a limitation of this app — it takes about five minutes, it is free, and no billing account is needed.

          1. Open the Google Cloud credentials page. console.cloud.google.com Sign in with the Google account that should own this app, then create a project if you have none.
          2. Configure the consent screen (left menu → OAuth consent screen). Choose External, give the app a name and your email, and save. You can leave it in Testing mode — add your own address under Test users and it works immediately.
          3. Create credentials → OAuth client ID → Web application.
          4. Add this exact address under both Authorised JavaScript origins and Authorised redirect URIs: — It must match character for character — no trailing slash.
          5. Copy the Client ID Google shows you and paste it here:

          A client ID is a public identifier, not a secret — it is meant to be visible in the page, and it only works from the origins you authorised above. It is stored in this browser only. If you would rather have server-verified accounts and cross-device sync, add a Firebase config in Settings instead; that path also turns this button on.

          Why there is no single central table

          CuacaMY is a static site: HTML, CSS and JavaScript on GitHub Pages, with no server of its own. There is nowhere for a shared database to run, so by default each visitor's account lives in their browser, in an IndexedDB database called cuacamy, object store users. You can see it yourself in any browser: open DevTools → Application → IndexedDB.

          That is genuinely private — nobody's password ever leaves their device — but it means this page can only show you the accounts on the device you are reading it on. It is not hiding the rest; there is no "rest" to fetch.

          If you want one real central database that you can open and read as the owner, add a Firebase config in Settings. Accounts then live in Cloud Firestore, in a Google Cloud project you own, in a collection called users — one document per account, visible in the Firebase console, with server-side security rules. The app switches over automatically and this panel will point at it.

          Firebase console Firestore security rules

          Password hashes and salts are never shown here and are excluded from every export. Deleting an account removes its record and its saved places from this device permanently.
